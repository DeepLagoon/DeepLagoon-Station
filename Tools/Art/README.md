# Установка HTTPS-маршрута редактора планшета

`install_tablet_nginx.py` — один файл для Linux с Python 3.9+ и уже работающим nginx с HTTPS-сертификатом. Дополнительные Python-пакеты не нужны. Скрипт запускают **на хосте nginx**, не на компьютере игрока. Он не устанавливает nginx, не выпускает сертификат и не меняет игровой клиент.

Скопируйте только `install_tablet_nginx.py` на сервер и выполните:

```bash
sudo python3 install_tablet_nginx.py
```

Значения по умолчанию:

- домен: `deep-lagoon-ss14.ru`;
- игровой HTTP/status-сервис: `http://127.0.0.1:1212`;
- публикуемый путь: `/art-tablet/`.

Если игровой сервер находится на другом хосте, укажите его доступный nginx HTTP/status-адрес:

```bash
sudo python3 install_tablet_nginx.py --upstream http://GAME_HOST:1212
```

Адрес upstream задаётся без завершающего `/`. При отдельном игровом хосте используйте адрес защищённой внутренней сети, если она есть: nginx передаёт туда авторизацию браузерной сессии.

Можно сначала посмотреть изменения без записи и reload:

```bash
sudo python3 install_tablet_nginx.py --dry-run
```

Другой домен, конкретный файл сайта или нестандартный основной конфиг:

```bash
sudo python3 install_tablet_nginx.py --domain art.example.org --upstream http://127.0.0.1:1213
sudo python3 install_tablet_nginx.py --site-config /etc/nginx/sites-available/deep-lagoon-ss14.ru
sudo python3 install_tablet_nginx.py --nginx-conf /path/to/nginx.conf
```

`--site-config` ограничивает поиск уже подключённым файлом. `--nginx-conf` нужен, если запущенный nginx использует этот основной файл через `-c`; проверять и перезагружать необходимо одну и ту же конфигурацию. Нестандартный запуск с другими глобальными параметрами или TLS на внутреннем порту, отличном от 443, этим установщиком не поддерживается.

## Что делает скрипт

1. Проверяет текущую конфигурацию через `nginx -T`, находит загруженные HTTP-блоки с точным `server_name` и `listen 443 ssl`, учитывает `include` и символические ссылки.
2. Проверяет, что upstream отдаёт страницу планшета и файлы TGUI. Если этого нет, завершает работу без изменения nginx.
3. Сохраняет исходные файлы и `manifest.json` в отдельный каталог `/var/backups/deeplagoon-art-tablet/`. Каталог конкретной копии доступен только root.
4. Атомарно добавляет только свой `location ^~ /art-tablet/`. Остальные маршруты, сертификаты, HTTP-редиректы и привязки портов не меняет.
5. Выполняет `nginx -t`, затем `nginx -s reload`, проверяет страницу, JS и CSS по публичному HTTPS-адресу с обычной проверкой сертификата. При ошибке после записи восстанавливает исходные файлы; если reload уже выполнялся — перезагружает исходную конфигурацию.

Повторный запуск не дублирует маршрут; изменение `--upstream` обновляет только блок между собственными маркерами. Чужой существующий `location` для `/art-tablet/` автоматически не перезаписывается. Изменение файла другим администратором во время установки останавливает автоматический откат этого файла, чтобы не затереть чужую правку; путь к резервной копии остаётся в выводе.

Публичный HTTPS-адрес должен быть доступен с самого хоста nginx. Если DNS указывает на другой фронтенд, там остаётся 404 или серверный `return`/`rewrite` перехватывает маршрут, финальная проверка завершится ошибкой с откатом. `nginx -T` читает конфигурацию на диске, поэтому перед запуском не оставляйте в ней несвязанных неприменённых изменений, которые нежелательно включить при reload.

При необходимости ручного возврата в `manifest.json` указаны исходный `path`, соответствующий файл `backup` и SHA-256 до/после установки. Восстановите перечисленные файлы из указанной резервной копии, выполните `sudo nginx -t`, затем `sudo nginx -s reload`. Сначала убедитесь, что после установки эти файлы не правились отдельно.

В конфигурации игрового сервера должно остаться:

```toml
[art]
tablet_url = "https://deep-lagoon-ss14.ru/art-tablet/"
```

Скрипт этот параметр не записывает. После установки повторно нажмите «Открыть для планшета» в игре, чтобы получить свежую одноразовую ссылку. Публикация страницы не изменяет движок или подписанный WebView.

Семантика проверки, дампа конфигурации и reload описана в [официальной документации nginx](https://nginx.org/en/docs/switches.html).

## Проверка установщика

Проверки планирования, входных данных и отката без изменения рабочего nginx:

```bash
python3 -m unittest discover -s Tools/Art -p test_install_tablet_nginx.py -v
```

Реальная проверка nginx, HTTPS, URI, заголовков, повторного запуска и отката — только в одноразовом контейнере, без публикации портов хоста:

```bash
docker run --rm \
  --mount "type=bind,source=$(pwd)/Tools/Art,target=/art-tools,readonly" \
  --env DL_ART_NGINX_TEST=1 --env PYTHONDONTWRITEBYTECODE=1 \
  --entrypoint sh nginx:stable-alpine -c \
  'apk add --no-cache python3 openssl && python3 /art-tools/test_tablet_nginx_runtime.py'
```

Тест намеренно не запускается на обычном хосте: ему нужны и контейнер, и `DL_ART_NGINX_TEST=1`.
