# Визуальный diff карт в Pull Request

Инструмент Station обнаруживает изменения `Resources/Maps/**/*.yml` и `.yaml`,
сравнивает их с merge-base PR и публикует один обновляемый комментарий
`github-actions[bot]` с изображениями **до | после | подсветка изменений**.
Добавление, удаление и переименование карты также обрабатываются.

## Подключение

После слияния этих файлов в **default branch** включённые GitHub Actions начнут
обрабатывать новые PR и новые коммиты в существующих PR автоматически.
`workflow_run` для публикации должен существовать в default branch.
Отдельный PAT, внешний сервер, GitHub Pages или дополнительный секрет не нужны.
Если настройка организации запрещает Actions создавать комментарии или писать
в ветки, разрешите эти операции для workflow: ему нужны `pull-requests: write`
и `contents: write`. Основные ветки и их protection rules менять не требуется.

Публикация создаёт отдельную orphan-ветку **`map-diff-previews`**. В ней находятся
только PNG-превью, сгруппированные по `pr-N`; исходники Station туда не копируются.
URL содержат SHA коммита изображений, поэтому обновление другого PR не ломает
старые ссылки. Новая публикация заменяет каталог текущего PR, сохраняя остальные.
История этой ветки растёт вместе с превью; не включайте её в правила сборки релизов.
В публичном Station картинки видны непосредственно в комментарии. Для закрытой
копии репозитория GitHub может не отображать приватные raw-изображения; полный
отчёт остаётся в artifact с теми же правами доступа, что и репозиторий.

В комментарии отображаются первые восемь превью. Полный набор, `index.html`,
отдельные изображения, исходные рендеры в полном разрешении и `report.json` доступны в Actions artifact
**`station-map-diff`** в течение 30 дней. Для просмотра распакуйте artifact
и откройте `index.html`. Сбой отдельной карты явно указан; остальные карты
обрабатываются дальше. Логи ошибочных рендеров хранятся отдельно 7 дней.

## Что сравнивается

Сохранённые тайлы (имена прототипов, варианты, флаги, поворот), объекты,
непосредственно размещённые на гридах (прототип, координаты, поворот),
и декали формата DecalGrid v2. Смена UID и нумерации палитры тайлов игнорируется;
сопоставление нескольких гридов использует геометрию и имена. Перемещение объекта
показывается как удаление старого и добавление нового размещения.

Обе YAML-версии рендерятся **с движком и прототипами текущего PR**. Это позволяет
сравнить размещение при одинаковом наборе ресурсов; это не воспроизведение
исторической версии игры. Содержимое контейнеров, метаданные пересохранения,
свойства компонентов и сущности вне гридов не входят в статистику размещения.
Спавнеры при загрузке могут породить объекты; цветные отметки рассчитываются
по сохранённому YAML, а не по случайной разнице пикселей. NPC AI отключён.

`Render PR map diff` работает на `pull_request` с read-only токеном и без secrets.
`Comment PR map diff` запускается на `workflow_run`, исполняет только код default
branch и проверяет связь run → PR и актуальность SHA. Artifact используется
только как JSON/PNG-данные. Код и команды из него не выполняются.

## Локальный запуск

Из корня Station, после подготовки pinned engine и сборки MapRenderer:

```powershell
py -m pip install -r Tools/map_diff/requirements.txt
dotnet build Content.MapRenderer/Content.MapRenderer.csproj
$baseSha = git rev-parse main
$headSha = git rev-parse HEAD
py Tools/map_diff/build.py plan --base $baseSha --head $headSha --output .local/codex/map-diff/report
py Tools/map_diff/build.py build --output .local/codex/map-diff/report
```

Для одного произвольного сохранения, без записи в `Resources`:

```powershell
dotnet bin/Content.MapRenderer/Content.MapRenderer.dll --snapshot C:/maps/example.yml --output .local/codex/map-diff/snapshot
```

Проверки инструмента:

```powershell
py -m unittest discover -s Tools -p 'test_ci_map_diff.py' -v
node --test Tools/map_diff/publish.test.cjs
```
