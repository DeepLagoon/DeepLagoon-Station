# Локальный прототип квартир

Система включена по умолчанию. Игрок прибывает автобусом на жилую остановку,
заходит в лифт и выбирает номер квартиры на пульте.
HOST-команды сохранены для отладки и восстановления. Терминал внутри квартиры
позволяет хозяину открыть редактор и магазин шаблонов. Для гостей достаточно
войти в один лифт и знать номер квартиры. Мебель задаёт бесплатный каталог прототипа;
платные шаблоны приобретаются за Lagoon Coin.

## Шаблоны, покупки и лобби

Кнопка «Квартира и обустройство» в лобби открывает тот же магазин, что кнопка
«Шаблоны квартир» в консоли и редакторе обстановки. Базовая `DLApartmentBasic` бесплатна.
Для нового шаблона задайте `map`, `price` (целое число LC), `available: true`, размеры,
точку прибытия, защищённые клетки лифта и каталог мебели. `available: false` исключает
шаблон из магазина. У карты должен быть закреплённый пульт лифта. Цена проверяется
на сервере; карта проверяется загрузкой до списания средств. Дополнительные платные
планировки в поставку не добавляются без соответствующих карт.

Покупка сохраняется для аккаунта и не оплачивается повторно. Незавершённая покупка
повторяется с прежним идентификатором операции LC; это защищает от двойного списания
при повторе запроса или перезапуске. Сохраняется отдельная расстановка каждого шаблона.
Выбор меняет номер квартиры, но не перемещает находящихся внутри игроков: нужно
спуститься на остановку и ввести новый номер. Старый грид живёт до выхода гостей.

Сохранения временного прямоугольного шаблона автоматически мигрируют на бесплатный
базовый; прежняя расстановка остаётся резервной записью. Для ещё открытой временной
квартиры магазин содержит отдельную кнопку выхода на остановку.

В лобби можно выбрать шаблон и сохранить расстановку без живого персонажа. Редактор
проверяет права пользователя и статус лобби на сервере. При обычном и позднем входе
персонаж появляется на свободной кровати выбранной квартиры.

## Регулятор атмосферы

`DLApartmentAtmosphereController` использует спрайт датчика воздуха. Бесплатный
предмет `DLAptAtmosphere` доступен в каталоге обстановки базовой квартиры, максимум
один. Для других шаблонов добавьте его в `catalog`. Закреплённое устройство на
гриде с `ApartmentGrid` регулирует все клетки пола только этой квартиры, без труб
и питания: 101,325 кПа, 20 °C, только кислород и азот. Вне квартиры оно не работает.
Окно открывается обычным взаимодействием; кислород задаётся целым процентом 0–100,
азот автоматически дополняет его до 100. По умолчанию используется смесь 21/79.
Состав сохраняется в дельте квартиры и переживает выгрузку, перезапуск и перестановку
мебели. Несколько устройств на одном гриде используют общую настройку. Удаление
последнего возвращает стандартный безопасный воздух; повторная установка применяет
сохранённый состав. Гриды остановки и соседних квартир не меняются.

Контроллер использует неизменяемые смеси существующего режима безопасной атмосферы:
остальные газы исключаются при обновлении всех клеток, а последующие попытки добавить
их в эту смесь игнорируются. Температура и давление поддерживаются тем же механизмом.

## Запуск сервера

Готовая остановка сохранена в `/Maps/_DeepLagoon/Apartments/residential_stop.yml`.
Исходный ранний экспорт (237 сущностей) оставлен рядом в файле `residential_stop`.
Последний экспорт пользователя (325 сущностей) сохранён в `residential_stop.authored.yml`.
Рабочая карта сохраняет его планировку/пол/декали/направления портов и проводку;
недостающие соединения питания дополнены. Она содержит 336 сущностей и 445 клеток пола.
Генератор, SMES и подстанция закреплены; генератор питает HV-сеть через подстанцию,
MV-сеть заряжает APC, LV-сеть питает приборы. SMES предварительно заряжен как резерв
на HV-сети. Его вход зарядки не подключён отдельным терминалом.
Гравитация задана постоянной. `GridEnvironment.safeAtmosphere` поддерживает на всех
клетках пола неизменяемый безопасный воздух около 101 кПа при 20°C, включая площадку
стыковки. Вне пола остаётся космический вакуум. Загрузчик включает этот режим также
для существующей остановки и старых экспортов без настройки атмосферы. Debug-светильники пользователя сохранены.

`ApartmentStopLoaderSystem` загружает одну остановку после начала каждого раунда,
на любой выбранной игровой карте, включая обычную Dev и `DLApartmentDev`.
Для остановки создаётся отдельная инициализированная космическая карта, изолированная
от пространства раунда. Автобус обслуживает её через существующий межкартовый маршрут.
Карта регистрируется как включённое FTL-направление без требования диска координат;
whitelist допускает только `TransitShuttle`, поэтому обычные шаттлы не получают
направление в своих консолях. Без регистрации `FTLToDock` отменяет поездку до запуска FTL.
Загрузка не зависит от `shuttle.grid_fill`, station-прототипа и ручного `loadgrid`.
Если в раунде уже есть действующая остановка квартир, используется она, без второй копии.
Удаление автоматически созданной остановки администратором не запускает её повторное
создание до следующего раунда. Ошибка загрузки удаляет временную карту вместе с гридом
и записывается в серверный журнал; автоматических повторных попыток каждый тик нет.
После исправления файла для повтора выключить и включить `deeplagoon.apartments_enabled`.
Путь к карте задаётся `deeplagoon.apartments_stop_map` (по умолчанию файл выше).
Явное `apartments_enabled = false` в конфигурации сервера отключает автозагрузку.
Для повторной подготовки из исходного файла:

```powershell
node Scripts/prepare-apartment-stop.cjs Resources/Maps/_DeepLagoon/Apartments/residential_stop.authored.yml Resources/Maps/_DeepLagoon/Apartments/residential_stop.yml
```

Если «Скачать черновик grid» висит без диалога, проверить сборку клиента: новый
TGUI использует `draftFileStart`/`draftFileChunk`, которые должны присутствовать в
`Content.Client.dll`. Обновление одного TGUI без C#-сборки не обеспечивает экспорт.

Из корня DeepLagoon-Station:

```powershell
.\Scripts\run-apartment-prototype.ps1 -Build
```

Сервер слушает только `127.0.0.1:1214`, работает с тестовой картой Dev и отдельным
каталогом данных `bin/ApartmentPrototypeData`. Для подключения нужен собранный клиент этой рабочей копии:

```powershell
.\bin\Content.Client\Content.Client.exe --connect --connect-address 127.0.0.1:1214 --username ApartmentTester
```

Выполнить `startround` в игровой консоли (клавиша `~`). Режим Sandbox;
тестовая карта предлагает роль Passenger. Выбрать её через «Присоединиться».
Затем выполнить:

```text
apartment enter
apartment edit
apartment leave
apartment status
```

Посещение: хозяин выполняет `apartment invite <имя>`, приглашённый самостоятельно
выполняет `apartment visit <хозяин>`. Команды входа/посещения в прототипе требуют HOST.
Для локального подключения HOST выдаётся существующим механизмом `console.loginlocal`.

## Жилой маршрут существующего автобуса

Для игрового входа HOST не нужен. Квартиры уже включены по умолчанию;
для движения автобуса нужен `nf14.publictransit.enabled`. Готовая остановка загружается
автоматически. Для создания альтернативной остановки разместить `DLApartmentBusStop` на свободной
клетке пола и закрепить его. Это точка возвращения: под неё нельзя выбирать стену,
докинг-порт или клетку с мебелью. На том же гриде нужен обычный порт автобуса
`AirlockExternalGlassShuttleTransit` (приоритет `DockTransit`).
Для локальной проверки допустимо поставить эту остановку на Dev.
Важно: маршрут автобуса хранит гриды, а не отдельные порты. На основном гриде Dev
уже есть остановка и порт `DockTransit`: второй порт на этом же гриде не создаёт
новую остановку, и автобус может продолжать выбирать старый порт. Для проверки
квартир достаточно поставить маяк на Dev и сесть в автобус у существующего порта.
Для отдельной новой остановки нужна отдельная платформа-грид с маяком и портом.
Порт должен быть закреплён на внешнем краю платформы и направлен стыковочной
стороной в космос. Удалить стену в клетке порта; перед ним не должно быть плиток
этого грида в области корпуса прибывающего автобуса. При отсутствии допустимой
стыковки обычный автобус использует прибытие в космос рядом с целевым гридом.
Если квартиры были явно отключены в конфигурации, включить
`cvar deeplagoon.apartments_enabled true` в терминале серверного процесса.
В игровой консоли клиента с правами HOST использовать
`sudo cvar deeplagoon.apartments_enabled true`: обычный `cvar` выполняется
на клиенте, где эта переменная с флагом `SERVERONLY` не зарегистрирована.

При включённых квартирах отмеченный грид добавляется в существующий маршрут автобуса,
в том числе на отдельной карте ЦК. Закреплённые обычные шлюзы на этом гриде автоматически
становятся входами в квартиры в течение секунды. Шлюзы с `Docking` исключены: они
пропускают пассажиров из автобуса. Нажатие на обычный шлюз открывает жилой маршрут;
сам шлюз остаётся закрытым, не получает урон и защищён от разборки, RCD и взлома ломом.
Для отправления автобус уже не обязан оставаться пристыкованным. Автоматических окон
при стыковке и квартирных действий в ПКМ-меню автобуса нет.
При отключении квартир, снятии маяка или переносе шлюза с жилого грида его обычное
поведение восстанавливается. Обычное нажатие на `DLApartmentTerminal` открывает отдельный
TGUI `ApartmentTerminal` с возвращением, обустройством и управлением гостями.
Правила серверной проверки одинаковы для меню и завершения перехода:

- Игрок жив и управляет тем же персонажем; находится рядом с входом или домашним
  терминалом без преграды. Для входа персонаж должен быть на гриде остановки.
- Для отправления шлюз закреплён на гриде с действующим маяком остановки.
- Переход занимает 3 секунды через DoAfter. Движение, повреждение, отключение или
  удаление входа или потеря действующей остановки отменяют отправление. До завершения вещи не изымаются.
- При успешном переходе снаряжение сдаётся существующему хранилищу и персонаж прибывает домой.
- Возвращение идёт на исходную остановку, независимо от положения автобуса.
  Если она исчезла, выбирается другая пригодная отмеченная остановка. Если исчезли все,
  вещи сохраняются в хранилище, выход сообщает об ошибке; нужны восстановление остановки
  или помощь HOST. Переход в космос автоматически не выполняется.

Квартиры не добавляются в общую линию автобуса. Дополнительный шаттл для каждой квартиры
не создаётся: автобус обслуживает ЦК, частный переход управляется транспортным адаптером.
Включение жилой линии не меняет стандартный таймер и алгоритм перемещения автобуса.

## Гости

В меню хозяина доступны приглашение, отзыв, открытие/закрытие входа и возвращение гостя.
Приглашать можно через шлюз входа до первого посещения квартиры;
это создаёт только права доступа, без загрузки грида. Новые приглашения у входа
доступны только живым игрокам того же грида в обычном радиусе взаимодействия
без преграды; сервер повторно проверяет это при нажатии кнопки. Список показывает
имена персонажей. Приглашение действует 5 минут, максимум 32 активных
приглашения; переприглашение обновляет срок. Эти права хранятся отдельно от grid: выгрузка
пустой квартиры не отменяет приглашение, а поездка гостя загружает её заново в пределах
общего лимита. Гость принимает приглашение кнопкой поездки
в меню шлюза на жилой остановке, затем проходит такую же сдачу снаряжения.

Закрытие входа отменяет действующие приглашения, но не выгоняет уже прибывших гостей.
Они могут вернуться самостоятельно, даже если хозяин отключился. Пока хотя бы один
участник остаётся подключён, квартира активна. Редактировать интерьер может только хозяин.
При принудительном возвращении гостя владелец подтверждает действие; сидящий гость
отстёгивается, снаряжение возвращается. При невозможности безопасного возвращения он
остаётся в квартире. Прежнее приглашение в любом случае отзывается.

## Расширение

Квартиры и действующие остановки получают `ApartmentProtectedGrid` вместе со
штатными `ProtectedGrid` и `PacifiedZoneGenerator`. Режим `wholeGrid` генератора
покрывает весь грид, включая сидящих персонажей, без генераторов отдельных комнат.
Пауза квартиры приостанавливает поиск посетителей зоны. Ограничения снимаются
при выходе из зоны; естественное умиротворение персонажа сохраняется.

Все объекты на жилом гриде защищены от разборки через строительные графы и RCD,
а также через альтернативное действие разборки предметов,
включая новые предметы и стыковочные шлюзы. Не используются списки мебели или
защитные компоненты на каждом предмете: проверка идёт по текущему гриду объекта.
Положительный урон посетителям и объектам блокируется, лечение разрешено.
Штатные флаги защищают от взрывов (также снаружи), ЭМИ, артефактов и враждебных NPC.
Пол нельзя разбирать, перестилать или изменять RCD. Редактор квартиры и админский
редактор сохраняют доступ к прямым изменениям грида/интерьера.

При потере последнего действующего маяка или отключении квартир динамически отмеченная
остановка восстанавливает существовавшие до этого настройки `ProtectedGrid` и генератора.
В готовой карте остановки защита задана постоянно и сохраняется при отключении функции.
Защита уже загруженных квартир сохраняется до выгрузки их гридов.

- `apartmentFurniture`: ID, ключ локализации, entity-прототип, размер занимаемого
  прямоугольника, максимум экземпляров, блокирует ли проход. Размер должен соответствовать
  реальной коллизии сущности; первая версия поддерживает размещение по целым клеткам.
- `apartmentTemplate`: версия, размеры, пол, стены, площадка прибытия, каталог, лимиты,
  исходная мебель. `id` каждой исходной позиции постоянен, даже если её переставили в YAML.
- Каталог и шаблоны: `Resources/Prototypes/_DeepLagoon/Apartments/apartments.yml`.
  Локализации: `_DeepLagoon/apartments.ftl`.
- `ApartmentLayout`: чистые общие правила размещения, получение обстановки из разницы
  и сворачивание конечного состояния в компактную разницу. У него нет зависимости от ECS,
  интерфейса, кошелька или базы.
- `IApartmentLayoutStore`: сменная граница хранения. Текущий SQLite-адаптер пишет
  в `apartments-prototype.db`, отдельно от основного аккаунтного хранилища.
- `ApartmentSystem.Enter/Leave`: точки подключения будущего IC-транспорта.
  Редактор и сохранения не зависят от того, каким способом игрок прибыл на ЦК.
- `ApartmentEditorSystem`/`ApartmentPreviewOverlay`: клиентский черновик и отрисовка
  текстур без создания физических призраков. TGUI управляет планом, сервер получает только применение.

## Состояние и границы

Сохранение содержит версию схемы, ID/версию шаблона, ревизию, убранные исходные объекты,
изменённые исходные объекты и добавленную мебель. Шаблонные объекты без изменений не записываются.
Несовместимая версия не сбрасывает сохранение: вход отказывается до появления миграции.
Продакшен-миграции и учёт купленных экземпляров нужны перед включением платного каталога.

На посещаемую квартиру создаётся один grid. Есть две общие служебные карты с одинаковой
статичной атмосферой: активная и замороженная. Освещение постоянное, без отдельных ламп;
grid не создаёт собственную симуляцию атмосферы. При отсутствии подключённых участников
grid переносится на карту на паузе вместе с телами и содержимым. При возвращении оживает.
Пустые квартиры без тел выгружаются через `deeplagoon.apartments_empty_timeout` секунд.
Число загруженных квартир ограничено `deeplagoon.apartments_loaded_limit`.
Длительная заморозка с телами пока занимает место в этом лимите: отдельного вытеснения тел в криохранилище ещё нет.

Снаряжение сохраняется реальными сущностями на карте на паузе и выдаётся в прежние слоты/руки.
Если слот больше не подходит, вещь остаётся у точки возвращения. Вложенное содержимое сохраняется вместе с вещью.
Временная одежда удаляется при выходе. Интерьер переживает перезапуск, тела и вещи — только текущий раунд.
Находящиеся дома персонажи исключены из награды LC за игровое время.

Это прототип для локальной проверки, ещё не безопасная публичная IC-зона:
остаются полный аудит имплантов/способностей, расширения, защита мебели от всех способов разрушения,
режима совместного редактирования и нагрузочных замеров на живом сервере.
