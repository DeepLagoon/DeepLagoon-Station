# Тикеты ahelp в игре и Discord

**Проект системы.** F1 открывает тикеты. Игровой сервер хранит переписку и назначает ответственного, а DeepLagoon Bot отображает те же тикеты в Discord. При входе администратор получает очередь и историю с сервера. Звук нового обращения и напоминания доставляются отдельными событиями.

В MOLOT за основу взяты очередь обращений, карточка с ответственным и напоминание про очередь без ответственных. В DeepLagoon назначение общее для обеих площадок, а история переживает смену раунда и перезапуск игрового сервера. [Панель MOLOT](../../../MOLOT-BlueMoon-Station/code/modules/admin/admin_ticket_panel.dm) · [Напоминания MOLOT](../../../MOLOT-BlueMoon-Station/code/controllers/subsystem/ticket_ping/ticket_ss.dm)

## Игровая панель

- **Игрок.** F1 открывает форму нового обращения или текущее обращение по аккаунту. Первое отправленное сообщение или изображение создаёт тикет с номером. Последующие отправки добавляются в него, пока он открыт. В карточке видны номер, состояние, переписка и поле ответа с иконкой файла.
- **Администратор.** Слева очередь с фильтрами «Новые», «Мои» и «В работе». Строка содержит номер, игрока, возраст тикета, ответственного и отметку непрочитанного. Справа переписка, вложения, поле ответа и кнопки «Взять», «Решить», «Отклонить», «Закрыть». У кнопок достаточно подписей. «Отклонить» открывает одно обязательное поле причины.
- **Действия над игроком.** Сохранить отдельное окно, список банов, заметки, кик, бан, респавн и слежение с действующими проверками прав. Сохранить поиск по игрокам и закрепление игроков. Из списка игроков администратор по-прежнему может начать разговор. Первое сообщение создаёт тикет сразу с этим администратором в качестве ответственного. Кнопки работают с исходным игровым аккаунтом, а для действий над текущей сессией и сущностью сервер проверяет их наличие.
- **Режимы отправки.** «Только администраторам» добавляет служебную запись. Переключатель `Bwoink?` управляет старым звуком у игрока для конкретного публичного ответа. Он доступен при отправке публичного сообщения, в том числе вложения. В обычном Discord-сообщении администратора действует то же поведение, что при включённом переключателе в игре. [Текущая панель](../../Content.Client/Administration/UI/Bwoink/BwoinkControl.xaml) · [Текущий звук игрока](../../Content.Shared/CCVar/CCVars.Sounds.cs)

## Жизненный цикл

| Состояние | Действия |
| --- | --- |
| **Новый** | Игрок может дополнять обращение. Администраторы с `Adminhelp` могут читать его, писать служебные заметки и нажать «Взять». |
| **В работе** | Ответственный отвечает игроку и может решить, отклонить с причиной или закрыть тикет. Остальные администраторы читают его и могут оставлять служебные заметки. |
| **Решён** | Игрок получает результат. Ответственный получает 1 LC. Тикет уходит из активной очереди. |
| **Отклонён** | Игрок получает причину. Тикет уходит из активной очереди. |
| **Закрыт** | Игрок получает статус. Тикет уходит из активной очереди. |

Операция «Взять» обновляет запись только при состоянии «Новый» и пустом ответственном. Игра и Discord вызывают одну операцию. При одновременном нажатии побеждает первый зафиксированный запрос, а второму администратору показывается актуальный ответственный. Повтор того же запроса возвращает уже сохранённый результат. Состояние и право на действие проверяются на сервере при каждом нажатии и каждой отправке. Администратор не может взять своё обращение, созданное как игрок.

Отключение игрока или администратора сохраняет состояние. Если у ответственного отозвали `Adminhelp`, тикет возвращается в очередь с записью в журнале. Вход, выход и бан игрока отображаются тихими служебными событиями. После завершения следующее обращение получает новый номер. При отсутствии игрока финальный статус и причину можно доставить при следующем входе из серверного журнала.

## Уведомления

| Событие | Администраторы в игре | Игрок |
| --- | --- | --- |
| Создание игроком | Один новый звук из `oh-oh-icq-sound.mp3` для активных администраторов с `Adminhelp`, если у получателя включён звук ahelp | Тикет появляется в F1 |
| Новое сообщение, изображение или служебная запись | Счётчик непрочитанного без звука | Публичный ответ администратора использует прежний звук по действующим правилам |
| Просроченный тикет без ответственного | Красная строка «Есть не взятые и никем не рассмотренные тикеты» и один новый звук | — |
| Вход, открытие панели, загрузка истории, смена статуса | Обновление интерфейса без звука | Обновление статуса |

Предлагаемый порог напоминания — 3 минуты с создания, повтор — раз в 3 минуты. Оба интервала задаются на сервере. На один слот в каждом интервале отправляется одно напоминание, сколько бы обращений ни ждало. Напоминание получают администраторы без тикетов в статусе «В работе». Если все заняты, сервер ждёт свободного администратора. Просмотр и новые сообщения таймер не меняют. Взятие исключает тикет из напоминаний. При возвращении в очередь отсчёт начинается заново. Публичный ответ в тикете, который первым открыл администратор, использует прежний звук игрока.

В клиентские ресурсы добавить Ogg Vorbis из аудиодорожки приложенного MP3 длительностью около 0,52 с. Оставить `/Audio/Effects/adminhelp.ogg` для игрока. События для администраторов имеют ID для устранения повторов, а снапшоты и дозагрузка истории их не воспроизводят. Discord-сообщения бота идут без упоминаний. Уведомления самого клиента Discord зависят от настроек пользователя. [Discord Message Resource](https://docs.discord.com/developers/resources/message#allowed-mentions-object)

## Каналы Discord

1. Bot создаёт приватный текстовый канал `ahelp-<номер>` в категории `1571644573258748024`. Участники — автор с привязанным Discord-аккаунтом, роль ahelp-администраторов и бот. Автор и назначенный администратор могут писать и прикреплять файлы. Остальные ahelp-администраторы могут читать и брать свободные тикеты. Bot и Station проверяют полномочия при каждом действии. Серверное разрешение Discord `Administrator` обходит ограничения чтения канала. [Discord Permissions](https://docs.discord.com/developers/topics/permissions)
2. В `1554501569146388502` публикуется один embed на тикет, например **Игрок Seln создал тикет #4821** · **16:24 МСК** · **Открыть тикет**. Использовать Discord timestamp и ссылку на созданный канал. В ленту не попадают текст обращения, причина отклонения и файлы. В самом канале закреплена компактная карточка с теми же четырьмя кнопками и актуальным состоянием. Причина вводится в модальном окне, ошибки действия видит только тот, кто его вызвал. [Discord Components and Modals](https://docs.discord.com/developers/platform/components)
3. Служебные записи из режима «Только администраторам» копируются в отдельный закрытый для игрока канал `ahelp-<номер>-staff`. Он создаётся при первой служебной записи и поддерживает ответы и вложения администраторов. Так сохраняется нынешняя пересылка служебных сообщений в Discord при наличии игрока в основном канале. [Текущий режим Admin Only](../../Resources/Locale/en-US/administration/bwoink.ftl)
4. Непривязанный игрок может пользоваться F1. Bot создаёт канал для администраторов, а доступ автора действующей учётной записи добавляется после подтверждения привязки. Смена или отзыв привязки убирают старый доступ. Для взятия и завершения из Discord нужны роль ahelp и привязка к игровому аккаунту с действующим `Adminhelp` нужного слота. Вход в игру для этого не требуется. [Привязки DeepLagoon](../../Content.Server/_DeepLagoon/DiscordLink/DiscordLinkStore.cs)
5. Когда результат записан в серверный журнал, Bot удаляет основной канал, служебный канал при наличии и embed в ленте. Правило одинаково для решения, отклонения и закрытия. Канал ленты становится списком текущих обращений. Категория Discord вмещает 50 каналов, включая служебные. При заполнении тикет доступен в игре, а Bot повторяет создание в заданной категории по мере освобождения мест. [Discord Channel Resource](https://docs.discord.com/developers/resources/channel)

## Изображения и GIF

- В игре **Ctrl+V** отправляет вложение сразу, когда фокус стоит в поле ответа и буфер содержит файл изображения или пиксели. Текстовая вставка работает штатно. Картинка отправляется отдельным сообщением и не трогает набранный текст. Иконка файла открывает системный диалог и отправляет выбранное изображение сразу после выбора. Загрузка показывает прогресс и ошибку, а повтор использует тот же ID операции. [Вставка в GridEditor](../../TGUI/packages/tgui/interfaces/GridEditorReference.jsx) · [Загрузка файла в PDA Messenger](../../Content.Client/_DeepLagoon/PdaMessenger/PdaMessengerSystem.cs)
- В стандартном клиенте Discord пользователь вставляет изображение или выбирает файл через `+`, затем отправляет сообщение штатным способом. Bot получает уже опубликованное вложение. Автоотправка по одному `Ctrl+V` реализуема в игровом интерфейсе. [Discord File Attachments FAQ](https://support.discord.com/hc/en-us/articles/25444343291031-File-Attachments-FAQ) · [Discord Message Resource](https://docs.discord.com/developers/resources/message)
- Bot принимает вложения `MESSAGE_CREATE` как от игрока, так и от администратора, и передаёт байты в Station. В обратную сторону Bot загружает их в Discord как файлы. Изображения доступны после переподключения независимо от срока жизни ссылки CDN. Анимация GIF сохраняется, когда источником был GIF-файл или буфер содержал его байты. Если ОС положила в буфер только растровый кадр, передаётся этот кадр. [Подписанные ссылки Discord CDN](https://docs.discord.com/developers/reference#signed-attachment-cdn-urls)
- Приём ориентируется на формат файла. PNG, JPEG, GIF, WebP и APNG получают превью с сохранением анимации. Для BMP, TIFF, AVIF, HEIC, SVG и других распознаваемых форматов сервер готовит безопасное превью через декодирование или растеризацию. Оригинал доступен файлом, если превью для формата недоступно. SVG как активный документ в интерфейсе не открывается. Поддержку конкретных кодеков проверить на релизном клиенте. Неизвестный или повреждённый файл возвращает ошибку. Предлагаемый первоначальный лимит — до 20 МиБ на файл, с отдельными бюджетами на декодированные пиксели, кадры и объём загрузок. [Загрузка файлов через Discord API](https://docs.discord.com/developers/reference#uploading-files)
- Хранение и выдача файлов привязаны к ID сообщения и праву на чтение тикета. История содержит метаданные и миниатюры по запросу, полные изображения загружаются отдельно с проверкой доступа. В игровом WebView отображаются данные с сервера. Нативный режим сохраняет текст, состояния, действия и выбор файла. Вставку изображений в нативном режиме нужно подтвердить на официальном клиенте. Если доступный интерфейс буфера отдаёт только текст, для полного паритета потребуется поддержка в RobustToolbox.

## Хранение, синхронизация и LC

**Station.** В существующую БД добавить записи тикетов, неизменяемые события переписки и действий, метаданные вложений и очередь доставки Discord. У тикета внутренний UUID и отображаемый порядковый номер внутри слота. При подключении нескольких слотов использовать префикс слота, чтобы ссылка однозначно указывала на обращение. Хранить также ID раунда создания, аккаунт игрока, ответственного, время в UTC, состояние, причину и версию. Длительные операции с БД, файлами и Discord выполняются вне игрового цикла. Сохранить действующий лимит частоты сообщений ahelp и применять ограничения к вложениям.

**История.** При входе и получении `Adminhelp` клиент получает снимок очереди и считывает выбранный тикет страницами. Между снимком и подпиской сервер отдаёт события после курсора. Дубли по номеру события игнорируются. Делать отметки прочтения по аккаунту и номеру последнего прочитанного сообщения. Игрок получает только свой текущий тикет и публичные события. История завершённых тикетов, включая вложения, доступна через штатный серверный журнал по номеру тикета. Серверный игровой лог содержит поисковые записи событий и ссылки по внутренним ID на защищённые данные, включая оригиналы вложений. Старый `LogBwoink` в текущем коде пустой, поэтому запись в журнал входит в объём работы. [SharedBwoinkSystem](../../Content.Shared/Administration/SharedBwoinkSystem.cs)

**Контракт Bot и Station.** Выделить доступный только сервису API ahelp со своими полномочиями. Bot читает очередь исходящих событий слота, возвращает подтверждения доставки и передаёт команды/сообщения из Discord. Station сопоставляет Discord-пользователя с игровым аккаунтом, проверяет владельца или `Adminhelp` и фиксирует изменение с записью события за одну транзакцию. Gateway-события дедуплицируются по ID Discord-сообщения или взаимодействия, игровые отправки — по ID операции. Текст пользователей экранируется при выводе. Сама очередь хранит ID канала и сообщения, поэтому сообщения бота не уходят обратно в игру.

**Повторы.** При недоступности Discord игра принимает тикеты и сообщения, а Bot догоняет очередь при восстановлении связи. При перезапуске Bot сверяет каналы по маркеру UUID в теме канала и дочитывает публикации после последнего подтверждённого Discord ID. Маркер события в исходящей публикации позволяет восстановить соответствие после тайм-аута, поскольку окно дедупликации Discord `nonce` ограничено по времени. [Discord Create Message](https://docs.discord.com/developers/resources/message#create-message)

**Завершение и удаление.** Station сохраняет первую принятую команду завершения и приостанавливает новые игровые ответы. Если канал Discord уже существует, Bot закрывает запись, фиксирует границу по ID сообщения в каждом канале и дочитывает публикации до этой границы, включая вложения. После их сохранения Station фиксирует финальный статус, доставляет результат игроку в игре и ставит удаление Discord-каналов в очередь. При временной недоступности Discord в карточке виден статус «Завершается», а Bot продолжает с сохранённого шага. Тикет без созданного или создаваемого Discord-канала завершается сразу. Очистка Discord и выплата LC повторяются независимо.

При завершении раунда Station закрывает открытые тикеты без начисления LC. После падения сервера эта операция восстанавливается при следующем запуске. Пока бот сохраняет переписку и удаляет канал предыдущего обращения, игрок уже может открыть новое.

**Награда.** При переходе «В работе → Решён» в той же транзакции создаётся задача начисления на игровой аккаунт ответственного. Обработчик переиспользует операции кошелька LC с ключом `ahelp:resolve:<UUID>` и суммой 1. Для слотов с отдельной БД задача уходит в общую экономику через узкую операцию AccountService с проверкой записанного решения. Bot не задаёт сумму или получателя. Повтор, перезапуск и одновременное завершение из двух интерфейсов дают одно начисление. Закрытие и отклонение не создают платёж. [Операции LC в Station](../../Content.Server/Database/ServerDbBase.Currency.cs) · [AccountService](../../Tools/DeepLagoon.AccountService/Program.cs)

## Порядок реализации и приёмка

1. **Station и БД.** Реализовать модель, операции, журнал, полноту истории и клиентскую очередь. Проверить параллельное взятие, повтор отправки, вход администратора после начала переписки и восстановление после перезапуска процесса и смены раунда.
2. **Bot.** Подключить тестовые ленту и категорию, затем проверить круговой обмен, роли и привязки, гонку «Взять» между играющим и офлайн-администратором, причину отклонения, повтор после падения и удаление. При занятой категории проверить сохранение обращения в игре и отложенное появление канала. Приёмка включает проверку, что игрок не видит служебные записи ни в игре, ни в Discord.
3. **Аудио и медиа.** Проверить, что создание даёт один новый звук, 20 сообщений отвечающего игрока проходят тихо для всех администраторов, история при повторном входе молчит, игнорируемые тикеты напоминают одной строкой и одним звуком, а взятые больше не напоминают. Для обеих ролей прогнать вставку, выбор файла, двустороннюю передачу PNG и анимированного GIF, редкий формат, повреждённый файл и прерванную загрузку. Проверить на официальном клиенте Windows и Linux, включая нативный режим, и выполнить проверки клиентской песочницы из `AGENTS.md`.
4. **Награда и переключение.** Проверить 1 LC получателю по выписке после повторного «Решить», перезапуска между решением и выдачей и обрыва ответа кошелька. Для отклонения и закрытия баланс остаётся прежним. На момент переключения дать завершить открытые старые диалоги или перенести их подтверждённую переписку в журнал. В новой версии F1, админ-панель и входящие Discord идут через тикеты. Отключить старые ahelp-маршруты `DiscordChatLink`, webhook и `send_bwoink` для переключённых слотов. Использовать `1554501569146388502` только после отключения старого логгирования в этот канал. Выпустить согласованные версии Station, Bot и AccountService на тестовый слот перед переключением основного. ## Настройка текущей реализации

Включение выполняется при запуске выбранного слота через `ahelp.tickets=true`. Для подключения Discord сгенерировать отдельный `ahelp.bot_token` длиной от 32 символов и передать его боту вместе с адресом status API выбранного слота на loopback. Порог и период напоминания задают `ahelp.reminder_seconds` и `ahelp.reminder_repeat_seconds`. Без маршрута бота игроки и администраторы могут работать с тикетами в игре. Для проверки dev использовать отдельные Discord-ленту и категорию.

Журнал и вложения находятся в `ahelp-tickets.db` в пользовательских данных слота. Хранилище SQLite использует WAL. Для просмотра последних событий есть команда `ahelp_log <номер> [до ID события]` с правом `Adminhelp`. Награда проводится через кошелёк, настроенный в БД этого слота. Перед включением на дополнительном слоте сверить конфигурацию экономики.

Обе игровые панели воспроизводят анимированные миниатюры в истории, позволяют выбрать файл для отправки и сохранить вложение целиком. В режиме CEF также можно вставить изображение из буфера обмена. Исходное уведомление предоставлено пользователем как `oh-oh-icq-sound.mp3`. В игровых ресурсах лежит его звуковая дорожка в Ogg Vorbis.
